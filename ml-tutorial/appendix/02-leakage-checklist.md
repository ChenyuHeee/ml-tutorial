# 附录 02：数据泄漏排查清单（强烈建议每章都过一遍）

## A. 字段层面的泄漏（最常见）
- 标签的同义字段：例如“是否退款”与“退款金额>0”
- 事后字段：例如“最终状态/最终评分/是否死亡/是否违约（已发生）”
- 聚合字段：例如“未来 30 天内的消费次数”（预测未来时不可能知道）

## B. 流程层面的泄漏（更隐蔽）
- 在切分前对全量数据做：
  - 均值/方差统计（`StandardScaler`）
  - 缺失值填充策略（median/mean）
  - 类别编码（尤其 target encoding）
- 用 test 数据参与了特征选择/调参

## C. 切分层面的泄漏
- 同一个用户的多条记录同时出现在 train/test
- 时间序列随机打乱

## D. 快速自测：你的模型“异常地好”吗？
如果你发现指标异常好（例如 AUC=0.99），立刻做：
1. 打乱标签训练（指标应接近随机）
2. 只用单个可疑字段训练（看是否“一个字段秒杀”）
3. 把切分方式换成更严格（时间/Group）

## E. 推荐做法
- 用 sklearn `Pipeline`/`ColumnTransformer` 固化 fit/transform 边界
- README 里写清楚：哪些字段被明确禁用，以及为什么
